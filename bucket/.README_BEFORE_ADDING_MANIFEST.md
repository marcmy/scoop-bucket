# 🚨 READ THIS BEFORE ADDING OR EDITING A MANIFEST 🚨

## GitHub API authentication is not optional in Actions

GitHub-hosted runners share public IP addresses. An unauthenticated request to
`api.github.com` can therefore hit the shared 60-requests-per-hour IP limit even
when this repository's workflow token still has its full authenticated quota.

A failed run may succeed immediately when retried on another runner. That does
**not** mean the manifest is fixed.

`GITHUB_TOKEN` is generated automatically for every GitHub Actions job. It does
not appear under the repository's manually configured Actions secrets. The
workflow exposes it as `GITHUB_TOKEN`, and ScoopInstaller/GithubActions maps it
to `SCOOP_GH_TOKEN` for scheduled/dispatch Excavator runs.

## Use the right pattern

### 1. Preferred: use Scoop's authenticated GitHub checkver mode

A plain `checkver.url` pointing at `api.github.com` is **not** enough to make
Scoop authenticate the request.

Use `checkver.github` for GitHub API endpoints. Scoop's GitHub checkver mode
uses `Get-GitHubToken` and adds the Authorization header when a token is
available.

```json
"checkver": {
    "github": "https://api.github.com/repos/OWNER/REPO/releases/latest",
    "jsonpath": "$.tag_name"
}
```

Arbitrary repository API endpoints work too:

```json
"checkver": {
    "github": "https://api.github.com/repos/OWNER/REPO/actions/artifacts?per_page=100",
    "script": [
        "$response = $page | ConvertFrom-Json"
    ]
}
```

A `checkver.script` that only parses `$page` reuses the authenticated response
Scoop already downloaded and should not make a second HTTP request.

### 2. Raw-response regex checks

GitHub mode supplies a default `$.tag_name` JSONPath when there is no
`checkver.script`. If a manifest intentionally applies a regex to the raw JSON
response instead, preserve that behavior with a trivial script:

```json
"checkver": {
    "github": "https://api.github.com/repos/OWNER/REPO/releases/latest",
    "script": "$page",
    "regex": "..."
}
```

The script suppresses the default JSONPath and returns the original response text
for the existing regex.

### 3. Custom API request: authenticate explicitly

Avoid making a second GitHub request inside `checkver.script`. If custom HTTP
logic is genuinely unavoidable, conditionally attach a GitHub token rather than
sending an anonymous request. Prefer Scoop's `Get-GitHubToken` so local
configuration and all supported token environment variables are respected:

```powershell
$token = Get-GitHubToken
$headers = @{
    'User-Agent' = 'Scoop-Checkver'
    'Accept' = 'application/vnd.github+json'
    'X-GitHub-Api-Version' = '2022-11-28'
}
if ($token) {
    $headers['Authorization'] = "Bearer $token"
}
$response = Invoke-RestMethod -Headers $headers -Uri 'https://api.github.com/repos/OWNER/REPO/...'
```

## Never do either of these

### Do not assume plain `checkver.url` authenticates GitHub API requests

```json
"checkver": {
    "url": "https://api.github.com/repos/OWNER/REPO/releases/latest"
}
```

That request is not put through Scoop's GitHub-authentication branch and can hit
the shared hosted-runner IP rate limit.

### Do not make a custom GitHub API request anonymously

```powershell
Invoke-RestMethod -Uri 'https://api.github.com/repos/OWNER/REPO/...'
```

### Do not send an unconditional bearer header

```powershell
$headers['Authorization'] = "Bearer $env:GITHUB_TOKEN"
```

Local checks may not have `GITHUB_TOKEN`. Use `Get-GitHubToken` and add the
header only when a token exists.

## Autoupdate hash URLs

`autoupdate.hash.url` is handled separately from checkver. Current Scoop
explicitly adds authentication for `api.github.com` hash URLs when
`Get-GitHubToken` returns a token, so existing GitHub API hash URLs can remain
as `url`.

## Workflow requirement

Any workflow that executes manifest checks must expose its automatically
generated token:

```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

This repository does that in Excavator and CI manifest-test steps. Do not remove
it because the repository has no manually added secret; `secrets.GITHUB_TOKEN`
is supplied automatically by GitHub Actions.

There is normally no need to set `SCOOP_GH_TOKEN` separately in Excavator:
ScoopInstaller/GithubActions maps `GITHUB_TOKEN` to `SCOOP_GH_TOKEN` when the
latter is not already set.

## Before committing a manifest

1. Search the changed manifest for `api.github.com`.
2. For checkver API endpoints, use `checkver.github`, not plain `checkver.url`.
3. Use `checkver.script` only to parse `$page` whenever practical.
4. If a script makes its own GitHub request, use `Get-GitHubToken` and
   conditional Authorization.
5. Verify there is no unconditional Authorization header.
6. Validate the JSON.
7. Run the manifest check with a token.
8. Run it locally without a token when practical.
9. Remember: a green rerun after a rate-limit failure is not proof of a fix.

Useful audit command:

```powershell
rg -n "api\.github\.com|checkver|Invoke-RestMethod|Invoke-WebRequest|GITHUB_TOKEN|SCOOP_GH_TOKEN" bucket .github
```

## The one-sentence rule

> **GitHub API checkver: use `checkver.github`. Parsing: reuse `$page`. Custom
> HTTP: authenticate explicitly with `Get-GitHubToken`.**
